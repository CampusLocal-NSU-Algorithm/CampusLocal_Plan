# CampusLocal — 남서울대 자취방 추천 웹서비스 기획

> ⚠️ **2026-09 개정**: 매물 소스·검색범위가 바뀌었습니다. 아래 표와 `docs/데이터-API-ERD.md`가 최신 기준이고, 이 문서의 옛 섹션 1~3(실거래가 마커 중심 서술)은 참고용입니다.

## Context (왜 만드는가)

- **문제**: 남서울대(천안시 서북구 성환읍) 자취생은 방을 구할 때 시세가 적정한지, 통학이 얼마나 걸리는지, 주변 인프라가 괜찮은지를 각각 다른 데서 확인해야 한다. 한눈에 비교·추천해 주는 곳이 없다.
- **해결**: 사용자가 등록한 **현재 매물**을 지도에 찍고, 각 매물의 **① (실거래가 기준) 시세 적정성 ② 남서울대까지 도보·대중교통 시간 ③ 주변 인프라 ④ 건물 리뷰**를 묶어서 보여준다. 사용자가 예산·통학시간·선호 인프라를 입력하면 조건에 맞는 매물을 점수화해 추천한다.
- **인증/개인화**: 카카오 OAuth2 로그인. 로그인 사용자는 매물을 등록하고, 추천 조건을 저장하고, 즐겨찾기와 리뷰를 남긴다.
- **의도한 결과**: 개발 경험이 적은 3~4인 팀이 12~15주 안에 "실제 URL로 접속되는, 카카오 로그인·지도·매물등록·추천·리뷰가 되는 웹서비스"를 완성해 발표한다. 프론트엔드 마크업/스타일은 Claude Code로 생성한다.

## 확정된 전제 (사용자 답변 반영)

| 항목 | 결정 |
|---|---|
| 학교 | 남서울대학교(성환캠퍼스) 고정 — 통학시간 계산 기준점 |
| 집 검색 범위 | **천안시 전체** (동남구 44131 + 서북구 44133), 통학시간으로 필터·정렬 |
| 매물 소스 | **사용자 등록(직거래) 매물** — 네이버/직방 등은 공식 API 없음·크롤링 금지. 상세: `docs/데이터-API-ERD.md` §1 |
| 매물 신선도 | 등록 30일 후 자동 만료 + 끌어올리기 → 목록엔 현재 매물만 |
| 실거래가 용도 | 매물 시세가 적정한지 **검증·비교** + 동별 시세 지도 레이어 |
| 거리 계산 | **실제 도보 / 대중교통 시간** (매물 등록 시 계산·캐시) |
| 인증 | **카카오톡 OAuth2** (자체 회원가입 없음) |
| 필수 기능 | 로그인, 매물 등록, 개인화(조건 저장·즐겨찾기), **리뷰** |
| 배포 | 무료 호스팅 (PythonAnywhere) |
| 팀/기간 | 3~4명 / 12~15주 |
| 스택 | Python + Flask, 프론트는 Claude Code |

**확정 API 목록과 ERD 전체는 → `docs/데이터-API-ERD.md`**

## 1. 사용할 API

### (A) 시세 — 국토교통부 전월세 실거래가 (공공데이터포털)
- 원룸/자취방이 잡히는 3종을 모두 사용:
  - `getRTMSDataSvcRHRent` — 연립다세대 전·월세
  - `getRTMSDataSvcSHRent` — 단독/다가구 전·월세
  - `getRTMSDataSvcOffiRent` — 오피스텔 전·월세
- **파라미터**: `serviceKey`, `LAWD_CD`(법정동 시군구 5자리 = **44133**, 천안시 서북구), `DEAL_YMD`(YYYYMM), `pageNo`, `numOfRows`
- **응답**: XML. 주요 필드 — 보증금액, 월세금액, 전용면적, 건축년도, 층, 법정동, 지번, 계약년월/일, 계약구분(신규/갱신)
- **필터**: 응답에서 법정동명이 `성환읍`인 건만 사용 (필요 시 인접 `직산읍` 포함). 최근 **24개월** 수집.
- **한계**: 단독/다가구는 지번이 비어 있는 경우가 많음 → 지오코딩 실패분은 "동 중심 좌표 + 위치 근사 뱃지"로 표시.

### (B) 지오코딩 — 카카오 로컬 API `주소 검색하기`
- 지번주소(예: "충남 천안시 서북구 성환읍 성환리 123-4") → 위·경도
- REST API 키, 무료 한도 넉넉(일 10만). **서버 사이드 배치**로만 호출.

### (C) 통학 시간
- **대중교통**: ODsay 대중교통 길찾기 API (`searchPubTransPathT`) — 가입·키 발급 쉬움, 무료 일 1,000회. 출발=매물 좌표, 도착=남서울대 좌표.
- **도보**: 카카오모빌리티 보행자 길찾기 시도. 승인/한도 문제 시 **fallback = 직선거리(Haversine) × 1.3 ÷ 도보속도 4km/h**로 분(min) 환산.
- 결과는 매물(정확히는 지오코딩된 좌표)별로 DB에 캐시 → 웹 요청 시 재계산 안 함.

### (D) 인프라 — 소상공인시장진흥공단 상가(상권)정보 API (공공데이터포털)
- `storeListInRadius` — 남서울대 좌표 중심 반경 1.5km 내 상가
- 편의점 / 카페 / 음식점 / 병원·약국 / 마트 / 헬스장 / 세탁 등으로 분류해 `place` 테이블 저장
- 매물별 "반경 300m 내 선호 인프라 개수"를 추천 점수에 사용

### (E) 지도 — 카카오맵 JavaScript SDK
- 마커 + 커스텀 오버레이(가격 라벨), 클러스터러. JavaScript 키 필요, 배포 도메인 등록 필요.

### (F) 인증 — 카카오 로그인 REST API (OAuth2)
- 인가코드 → 토큰 → 사용자 정보(카카오 회원번호, 닉네임, 프로필 이미지)
- `redirect_uri`에 `http://localhost:5000/auth/kakao/callback` 와 배포 URL 둘 다 등록
- 구현은 `requests`로 직접(간단) 또는 `Authlib`

> **키 관리**: 공공데이터포털 `SERVICE_KEY`, 카카오 `KAKAO_JS_KEY` / `KAKAO_REST_KEY` / `KAKAO_CLIENT_SECRET`, `ODSAY_KEY`, Flask `SECRET_KEY` — 전부 `.env` (git 제외).

## 2. 아키텍처 — 수집(ETL) / 웹앱 분리

실시간으로 국토부 API + 지오코딩 + 길찾기를 돌리면 느리고 한도에 걸린다. **배치 스크립트로 SQLite를 채우고, 웹앱은 DB만 조회**한다. (PythonAnywhere 무료플랜의 외부요청 제한도 이 구조면 대부분 회피 — 수집은 로컬에서 하고 DB 파일을 배포에 올림.)

```
scripts/
  fetch_deals.py       # (A) 실거래가 24개월치 수집 → deal 테이블
  geocode_deals.py     # (B) 지번 → 좌표, building 테이블 구성/연결
  fetch_places.py      # (D) 상가정보 수집 → place 테이블
  compute_commute.py   # (C) building별 도보/대중교통 분 → commute_cache
  seed.py              # 남서울대 좌표 등 기준 데이터
```

웹앱이 실시간으로 호출하는 외부 서비스는 **카카오맵 JS(브라우저)**, **카카오 OAuth(서버)** 둘뿐.

## 3. 데이터 모델 (SQLite + SQLAlchemy)

- **User**: `id`, `kakao_id`(unique), `nickname`, `profile_image`, `created_at`
- **SearchProfile**: `user_id`(1:1), `max_deposit`, `max_rent`, `max_commute_min`, `room_types`(json), `preferred_infra`(json), `updated_at`
- **Building**: `id`, `name`, `address_jibun`, `address_road`, `lat`, `lon`, `geocode_status`(ok/approx/fail), `source_key`(unique)
- **Deal**: `id`, `building_id`(FK, nullable), `deal_type`(연립다세대/단독다가구/오피스텔), `deposit`, `monthly_rent`, `area_m2`, `floor`, `build_year`, `contract_ym`, `contract_type`, `dong_name`, `raw_jibun`
- **CommuteCache**: `building_id`(FK, unique), `walk_min`, `transit_min`, `updated_at`
- **Place**: `id`, `name`, `category`, `lat`, `lon`, `address`
- **Favorite**: `id`, `user_id`(FK), `building_id`(FK), `created_at` (unique 조합)
- **Review**: `id`, `user_id`(FK), `building_id`(FK), `rating`(1~5), `content`, `created_at`

> 매물 마커·리뷰·즐겨찾기는 모두 **Building 단위**로 묶는다. Deal은 한 Building의 거래 이력(가격 추이).

## 4. 추천 로직 (규칙 기반 점수화)

입력(로그인 시 SearchProfile 프리필): 최대 보증금, 최대 월세, 최대 통학시간, 방 유형, 선호 인프라 체크.

1. **필터**: 예산·통학시간·유형 조건을 넘는 Building 제외
2. **점수(0~100 가중합)**:
   - 가격 점수 — 예산 대비 여유가 클수록 ↑ (해당 Building 최근 거래 중앙값 기준)
   - 통학 점수 — `min(walk_min, transit_min)` 짧을수록 ↑
   - 인프라 점수 — 반경 300m 내 선호 카테고리 시설 수
   - 리뷰 점수 — 해당 Building 평균 별점 (리뷰 없으면 중립값)
   - 가중치는 `config.py` 상수로 (예: 0.35/0.30/0.20/0.15)
3. 상위 N개를 카드 리스트 + 지도 마커 강조

## 5-1. UI 흐름 & 화면별 구성요소 (디자인 캔버스 스펙)

> 플랜 승인 직후 첫 작업으로 이 스펙에 맞춰 **Claude Design 비주얼 목업**(아트보드: 랜딩 / 지도 / 건물 상세 / 추천 입력 / 추천 결과 / 마이페이지 + 화면 흐름 화살표)을 제작한다.

### 화면 흐름
```
[랜딩 /]
   │  "지도로 둘러보기"            "조건으로 추천받기"        "카카오로 시작하기"
   ▼                                  ▼                          ▼
[지도 /map] ──마커 클릭──▶ [건물 상세 /building/<id>]      [카카오 OAuth] ──▶ 원래 화면 복귀
   │                              │  즐겨찾기 ♥ / 리뷰 작성(로그인 필요 시 OAuth로)
   │  "이 조건으로 추천"           │
   ▼                              ▼
[추천 입력 /recommend] ──▶ [추천 결과] ──카드 클릭──▶ [건물 상세]
                                          "조건 저장"(로그인)
[상단바 프로필] ──▶ [마이페이지 /mypage] ── 내 조건 / 즐겨찾기 / 내 리뷰 ──▶ [건물 상세]
```

### 공통 레이아웃
- 상단바: 로고(CampusLocal) · 메뉴(지도 / 추천) · 우측 = 비로그인 "카카오로 시작하기" / 로그인 시 프로필 이미지+닉네임 드롭다운(마이페이지·로그아웃)
- 색: 남서울대 계열 블루를 포인트, 배경 화이트/라이트그레이. 모바일 우선 반응형.

### 화면별 요소
| 화면 | 핵심 요소 |
|---|---|
| **랜딩 `/`** | 히어로 카피("남서울대 자취방, 시세·통학·동네까지 한눈에") · CTA 3개 · 서비스 소개 3블록(시세 지도 / 통학시간 / 리뷰) · 데이터 출처 푸터 |
| **지도 `/map`** | 좌측 필터 사이드바(접이식): 보증금 슬라이더·월세 슬라이더·방 유형 체크·최대 통학시간·인프라 레이어 토글 / 우측 카카오맵: 가격 라벨 마커 + 클러스터 / 하단(모바일) 또는 우측(PC) 결과 카드 리스트 / 마커·카드 클릭 시 슬라이드업 상세 패널(요약: 시세 범위, 도보·대중교통 분, 평점, "자세히" 버튼) |
| **건물 상세 `/building/<id>`** | 헤더(건물명·주소·위치 정확도 뱃지) · 미니 지도 · 시세 카드(최근 거래 보증금/월세 범위 + Chart.js 추이) · 통학 카드(도보 N분 / 대중교통 N분·경로 요약) · 주변 인프라 리스트(300m 내, 카테고리 아이콘) · 리뷰 섹션(평균 별점 + 목록 + 작성 폼; 비로그인은 "카카오 로그인하고 리뷰 쓰기") · ♥ 즐겨찾기 버튼 |
| **추천 입력 `/recommend`** | 단계형 폼: 예산(보증금·월세) → 최대 통학시간 → 방 유형 → 선호 인프라 체크 → "추천 받기". 로그인 시 저장된 조건 프리필 + "내 조건으로 저장" 체크 |
| **추천 결과** | 상단 요약(조건 칩) · 랭킹 카드 리스트(순위·점수 배지·시세·통학·평점·♥) · 우측 미니 지도에 상위 마커 · 카드 클릭 → 건물 상세 |
| **마이페이지 `/mypage`** | 탭 3개: ① 내 추천 조건(수정) ② 즐겨찾기(카드 그리드, 해제 가능) ③ 내 리뷰(수정/삭제) |
| **로그인** | 카카오 OAuth 리다이렉트(자체 UI 최소) · 콜백 후 직전 화면으로 |
| **빈/에러 상태** | 지도 결과 0건, 지오코딩 실패 안내, API 오류 시 재시도 안내 — 목업에 포함 |

## 6. 기술 스택

## 9. 배포 (PythonAnywhere 무료)

1. 무료 계정 → Web 탭에서 Flask 앱(Python 3.x) 생성
2. Bash 콘솔에서 저장소 `git clone`, venv 생성, `pip install -r requirements.txt`
3. WSGI 파일: 프로젝트 경로 추가 + `from app import app as application`
4. 환경변수: WSGI 파일 상단에서 `os.environ` 주입 또는 서버에 `.env` 직접 생성(git 아님)
5. **SQLite 파일 경로는 절대경로**(`config.py`의 `basedir` 기준). 로컬에서 채운 `.db`를 업로드하거나, 콘솔에서 배치 스크립트 실행
6. Static 매핑(`/static/` → `static/`) 설정
7. **카카오 디벨로퍼**: 플랫폼에 배포 도메인 등록, 카카오 로그인 `redirect_uri`에 `https://<계정>.pythonanywhere.com/auth/kakao/callback` 추가, 카카오맵 JS 도메인에 배포 URL 추가
8. **무료플랜 외부요청 화이트리스트**: `kauth.kakao.com`·`kapi.kakao.com`(OAuth)가 허용돼야 함 — W2에 확인, 막히면 허용 요청. 배치성 호출(data.go.kr·dapi.kakao.com·ODsay)은 로컬에서 수행하므로 영향 적음
9. 갱신: 콘솔 `git pull` → Web 탭 "Reload"

## 11. 검증 방법 (착수 후)

- **ETL 스크립트**: 각 스크립트가 삽입한 행 수를 콘솔에 출력. `geocode_deals.py`는 성공/근사/실패 비율 리포트. `pytest`로 XML 파싱·점수 함수 검증.
- **로컬 실행**: `flask --app app run --debug` → 브라우저 체크리스트
  1. `/map`에 매물 마커 표시, 가격 라벨·클러스터 동작
  2. 필터(보증금/월세/유형) 적용 시 마커·목록 갱신
  3. 마커 클릭 → 상세 패널 → `/building/<id>`에 거래 이력·통학시간·주변 인프라
  4. **카카오 로그인** → 닉네임·프로필 표시 → 로그아웃
  5. 건물 상세에서 별점+리뷰 작성 → 목록·평균 별점 반영, 새로고침 후 유지
  6. `/recommend` 조건 입력 → 랭킹 결과. 로그인 시 조건 자동 채움, "조건 저장" 후 재방문 시 유지
  7. 즐겨찾기 토글 → `/mypage` 반영
- **배포 검증**: PythonAnywhere URL에서 1~7 재현. 다른 팀원 카카오 계정으로도 로그인 테스트.
- **발표 대비**: 네트워크 장애 대비 시연 녹화본 준비.
